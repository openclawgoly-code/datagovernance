# 前端 P1 计划：治理闭环与可运营性

- 日期：2026-10-30
- 状态：5 个 P1 changes 已实现并归档
- 前置：P0 的 7 个 changes 已全部实现并归档
- P0 计划：`docs/plans/2026-10-30-frontend-p0.md`

## 1. 目标

P0 已把资产、血缘、敏感、查询历史、看板和工作台做成可用入口。P1 解决四类 P0 明确留下的缺口：

1. 血缘只到列级，无法做表级影响判断；
2. 敏感复核只能逐条，扫描后处理效率低；
3. 查询历史只有当前页筛选，跨页记录找不到；
4. 看板 ACL 依赖手输用户名，工作台也缺少可处理的统一收件箱。

## 2. Changes

| Change | 能力 | 依赖 | 后端 |
|---|---|---|---|
| `p1-lineage-table-overview` | 表级血缘聚合、影响、资产跳转 | `lineage-workspace` | 新增数据集粒度图端点 |
| `p1-sensitivity-batch-review` | 批量确认/拒绝/调级、部分失败 | `sensitivity-workbench` | 新增批量复核端点 |
| `p1-query-history-server-filter` | 关键词/状态/用户服务端筛选、URL 保持 | `query-history-page` | 扩展现有 history 接口 |
| `p1-dashboard-acl-user-picker` | 空间成员搜索、排除已授权 | `dashboard-admin-ui` | 新增 ACL 候选端点 |
| `p1-workbench-governance-inbox` | 跨来源治理收件箱、移出/恢复 | `workbench-overview` | 新增 inbox 聚合 + 状态表 |

## 3. 实施顺序

1. **表级血缘**：后端聚合端点先落地，前端 `mode=dataset` 复用现有图组件；
2. **批量敏感复核**：后端批量事务与部分失败模型，前端当前页多选；
3. **查询历史服务端筛选**：扩展可选参数，前端移除客户端过滤；
4. **看板 ACL 用户选择器**：空间成员候选端点，替换手输用户名；
5. **治理收件箱**：最后做，因为它跨执行、告警、敏感三个来源，依赖前四项稳定。

前四项互相独立，可并行；收件箱建议最后合并。

## 4. 数据库与权限

- `p1-lineage-table-overview`、`p1-sensitivity-batch-review`、`p1-query-history-server-filter`、`p1-dashboard-acl-user-picker` 不新增表。
- `p1-workbench-governance-inbox` 新增：
  - `gv_inbox_state`：workspace + sourceType + sourceId 的 OPEN/DISMISSED 状态
  - 权限 `governance:inbox:read` / `governance:inbox:manage`
  - admin/developer：read + manage；viewer：read
- 批量复核复用 `metadata:sensitivity:review`；表级血缘复用 `metadata:lineage:read`；查询历史复用 `insight:read`；ACL 候选复用 `insight:dashboard:manage`。

## 5. 统一约束

- 所有新端点走 `WorkspaceContext`，不跨空间；
- 批量/聚合端点必须做来源权限过滤，不能用一个新权限绕过来源权限；
- 前端不直连 SuperSonic，不新增第二套 API 客户端；
- 前端复用 `PageHeader`、`FilterBar`、`EntityLink`、`StatusTag`、`SensitivityBadge`、`DatasetSearchSelect`；
- 表格、空态、错误态、加载态与 P0 保持一致。

## 6. 验收口径

- 表级血缘：同一对表的 5 条列级边聚合成 1 条表级边，边显示列级边数；
- 批量复核：10 条中有 1 条不存在时，9 条成功、1 条失败，审计一条 UPDATE；
- 查询筛选：跨页关键词、失败状态、用户名组合筛选，URL 可复现；
- ACL 选择器：只出现当前空间成员，已授权用户消失，非空间用户不可选；
- 收件箱：三类来源按严重度/时间统一排序，移出不改来源状态，恢复可回到列表；
- 所有 change：`pnpm type-check`、`pnpm build`、`mvn -pl backend/dg-app -am test` 通过。

## 7. P1 不做

- 工单流转、SLA、负责人分派；
- 看板版本回滚/自由拖拽；
- 历史结果快照/导出；
- 全文索引/搜索引擎；
- 跨空间收件箱；
- 自动解决告警或自动复核标签。

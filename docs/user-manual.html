数据治理平台使用手册

面向数据管理员、数据开发与运维值班人员。按"上手 → 干活 → 看住"的顺序编排，也可当速查手册跳读。文中每个状态名、字段名、错误码都取自平台实际返回，不是示意。

01开始之前

先记住一个词有两个意思

「空间」在本平台里是租户，不是别的

菜单里的空间管理管的是租户——一个部门、一个项目组的数据与任务的隔离边界。你的数据源、任务、执行记录、告警，全都属于某一个空间，跨空间彼此不可见。

而架构文档里的「Space」是模块边界概念（Metadata Space、Runtime Space……），跟你日常操作无关。两者同名不同物，沟通时说"空间"务必确认对方指的是哪个。

三种内置角色

每个用户在每个空间里各自持有角色——同一个人可以是 A 空间的管理员、B 空间的只读。

角色代码能做什么
空间管理员WORKSPACE_ADMIN本空间内全部操作，含成员管理、凭据管理、空间启停
空间开发者WORKSPACE_DEVELOPER建数据源、写任务、跑任务、配告警规则。不能管成员与凭据
空间只读WORKSPACE_VIEWER只能看。列表、详情、执行记录、审计日志

权限是细到操作的，全平台 83 个权限码，形如 metadata:datasource:read、control:job:run。菜单会按你的权限自动隐藏，但隐藏不等于拦截——直接输 URL 同样会被守卫挡回 403 页。本手册在每个操作旁标注它要的权限码。

登录与切换空间

  1. 用管理员给你的账号登录。首次部署时平台会创建一个 admin 账号；口令在应用首次启动的日志里以 WARN 打印一次，之后不再显示，请立即改掉。
  2. 登录后如果你在多个空间有身份，右上角会让你选一个空间进入。平台不替你猜——选错了后面看到的全是别的部门的数据。
  3. 顶栏的空间名随时可以点开切换。切换后整个界面的数据会全部换掉，这是正常的。
被停用的空间进不去

管理员可以停用一个空间。停用后该空间的调度任务不再触发，成员登录时也看不到它。如果你昨天还能进、今天空间不见了，先问管理员是不是停用了，而不是怀疑账号出问题。

02数据源管理

一切从这里开始：不先把数据源建起来并测通，后面的任务一个也编译不过去。

最后一列很重要——它决定了你在结构浏览里能看到几层树。这不是界面偏好，是平台按每种数据源的能力声明自动决定的。

HTTP 接口没有"库表结构"可言，所以它不画结构树。它也还不能作为同步任务的源端取数——建了之后能验证地址通不通、认证对不对，但拿它当数据源跑同步任务是做不到的。

新建一个数据源

需要metadata:datasource:create · 空间开发者及以上
  1. 进 数据源管理 › 数据源，点新建。
  2. 先选类型。表单会跟着类型变——选 PostgreSQL 出现主机/端口/库名，选 RestAPI 出现接口地址，选 Doris 可以填多个节点。别在意"为什么字段不一样"，那是按类型能力渲染的。
  3. 填连接信息与账号口令。口令提交后再也读不回来：平台把它加密存进凭据托管，接口返回里只有一个不可解密的 credentialId。要换口令就重填一次。
  4. 保存。此时状态是 草稿，还不能用。
  5. 点测试连接。通了状态变成 可用，同时记下服务端版本与耗时；不通则退回草稿并给出错误码。
DRAFT 草稿→ TESTING 测试中→ AVAILABLE 可用→ UNREACHABLE 不可达 · DISABLED 已停用→ ARCHIVED 已归档

手工测试失败会回到草稿，不会变成"不可达"。这个区分是有意的：你自己点的测试失败，多半是配置填错了；而"不可达"留给平台在后台巡检时发现的、原本好好的数据源突然连不上——那才是要惊动运维的事。

浏览库表结构

需要metadata:datasource:browse

在数据源列表点结构，抽屉里逐层下钻。每一层都是真的去目标库探的，不是缓存的猜测；再次打开会用快照加速，需要最新结构时点刷新。

分区表只显示父表

PostgreSQL 的分区表，平台只列出父表（如 payment），不列它底下那几十个 payment_p2024_01 分区——那是存储细节，列出来只会把你要找的表淹掉。要看分区布局，用自定义查询查 pg_class。

自定义 SQL 查询

需要metadata:datasource:query

结构抽屉里有 SQL 面板，可以直接对数据源跑查询、格式化 SQL、看结果。

  • 只允许查询类语句：SELECT / WITH / SHOW / DESC / EXPLAIN / VALUES。写 DELETE 会被直接拒掉。
  • 强制行数上限与超时。结果超过上限时会标记为已截断，别把截断的结果当成全量。
语法白名单是第二道防线，不是唯一一道

正式部署时，请为数据查询单独配一个只读数据库账号。白名单挡的是手滑，挡不了一个有写权限的账号被别的途径利用。

03数据集成

任务的一生：编译 → 发布 → 运行

这是本平台跟很多同类产品最不一样的地方，值得先读懂再动手：任务建好之后不能直接跑，中间隔着一步编译。

DRAFT 草稿— 编译 → VALIDATED 已校验— 发布 → PUBLISHED 已发布— 配调度 → SCHEDULING 调度中⇄ PAUSED 已暂停→ OFFLINE 已下线→ ARCHIVED 已归档

编译会去真的读源表和目标表的结构，逐条检查字段映射对不对、类型兼不兼容、数据源可不可用，然后生成一份"物理计划"。编译不过的任务发布不了，发布不了就跑不了。改过配置之后必须重新编译——界面上会提示"物理计划已过期"。

编译诊断分两级，都要看

错误会挡住发布，必须改。提醒不挡，但每一条都在说一件真会出事的事——比如"目标字段不是文本类型，写入依赖隐式转换"，或者"配置里有 2 个平台不认识的键"。

那条"不认识的键"尤其要当回事：拼错一个键名不会报错，配置只是静默失效。曾经有人把 fieldRules 写成 rulesByColumn，编译通过、执行成功，而明文身份证号原样落进了目标库。

八种任务类型

类型用途可配定时
整库迁移把一个库的结构和数据整体复制到另一个库，自动建表否
离线同步把一张表的数据搬到另一张已存在的表，可带过滤与清洗规则是
文件解析入库从 FTP/SFTP 读 CSV 或 JSON 文件入库是
接口解析入库调 HTTP 接口取数入库，支持分页是
实时任务常驻的流式作业否
批处理任务跑一段 SQL，或跑一个上传的 JAR / Python 包是

Python 任务跑注册过的 Python 制品，用于建模与训练是

做一次整库迁移

需要control:job:create · 源与目标数据源都已可用
  1. 进 数据集成 › 任务管理，新建，类型选整库迁移。
  2. 选源数据源与源库；表清单留空表示迁整个库。一次最多 200 张表，超过应当拆成几个任务——不然一次失败要重跑几小时。
  3. 选目标数据源与目标库。目标表不需要预先建好，平台会照着源表结构建。
  4. 命名规则按需要配：前缀、后缀、转小写。从 MySQL/Oracle 迁进 PostgreSQL 时请打开转小写——PostgreSQL 里不加引号的标识符会折成小写，不转的话你以后每次查询都得给表名列名加双引号。
  5. 想改建表语句的，用预览建表语句逐表看、逐表改。改过的会被原样执行，不会被下一次编译覆盖掉。
  6. 编译 → 发布 → 运行。
迁移失败是"部分成功"，不是"全都没发生"

200 张表的迁移在第 137 张失败时，前 136 张已经建好并灌满了数据——建表语句是隐式提交的，没法回滚。平台会如实告诉你"迁移在第 137/200 张表「xxx」失败（已成功 136 张）"，你从那张表接着跑就行。

离线同步与清洗规则

离线同步是最常用的任务类型。它与整库迁移的区别是目标表必须已经存在，好处是可以配字段映射、过滤条件和清洗规则。

九种清洗规则

在 数据集成 › 规则管理 里先把规则建好，再在任务的字段上挂。一个字段可以挂多条，顺序有意义——先去空格再判空，和先判空再去空格，对 " " 的结果完全不同。

规则做什么关键参数
时间日期格式把源端的日期串换成目标格式sourcePattern targetPattern
数值格式定标度、去千分位scale stripGrouping
缺失值填充空值填默认值defaultValue treatBlankAsNull
字符串替换查找替换，支持正则search replacement regex
大小写转换转大写／小写mode
增删前后缀加或去掉固定前后缀prefix suffix stripPrefix
去空格去首尾／全部空白mode
解密用托管凭据解密源端密文credentialId algorithm
脱敏见下mode keepPrefix keepSuffix saltCredentialId
脱敏：处理身份证、手机号、病历必读

脱敏有三种模式：PARTIAL 保留前后若干位、中间打码（320981********8923）；HASH 加盐哈希，盐来自凭据托管而不能写在规则参数里；FIXED 整体替换，连长度都不泄露。

两条硬约定：脱敏发生在数据落地之前，源表始终是明文，目标库拿到的已经是脱敏后的值；任何算不出来的情况一律返回星号，绝不放过明文——比如 HASH 模式没配盐，它不会退化成不加盐的哈希，而是直接给 ********。

被任务引用中的脱敏规则删不掉（返回 409）。这是有意的：删掉它，下一次同步就漏明文了。

配定时

发布后在任务详情里配 Cron。填之前可以用调度预览看接下来几次的触发时间——比对着 Cron 表达式硬想可靠得多。任务可随时暂停与恢复；暂停期间手工触发仍然有效。

整库迁移之外：批量建任务

选中源库里的多张表，一次生成多个离线同步任务。一次最多 200 个——再多就该考虑整库迁移了。名称冲突、缺字段映射的会逐条报出来，不会闷头建一半。

04数据开发

离线开发

数据开发 › 离线开发。写一段 SQL 直接对数据源执行，或者上传 JAR / Python 包来跑。SQL 形态要选执行数据源；JAR 形态必须指定入口类——平台不会去反编译 JAR 猜 main 方法在哪。

工作流编排

数据开发 › 工作流编排。把已有任务拖成节点，用边连起来。

  • 不能有环。编译时会检出来，并且告诉你环上具体是哪几个节点，不是只说一句"存在环"。
  • 边上可以配条件：按上游状态（成功/失败），或按上游写入行数。
  • 条件不成立时下游不执行，而整个工作流仍然算成功——"没跑"不是"失败"。
  • 取消父执行会级联取消正在跑的子节点。
节点引用的是任务，不是任务的内容

工作流里的节点存的是任务 ID。你改了那个任务的 SQL，工作流下次跑就用新的——不需要回来改工作流。

实时开发

当前版本可以配置和编译，但跑不起来

实时任务需要一个已注册的 Flink 执行器。没有的话，运行会明确失败并给出错误码 RTM_EXECUTOR_UNAVAILABLE——这是环境缺口，不是平台故障，别去查平台日志。平台刻意不假装"执行成功、写入 0 行"。

Python 任务同理，需要 K8s 执行器。

实时任务有自己的一套状态，和批任务不同——它没有"成功"这个终态，因为常驻作业跑得好好的时候既不是成功也不是失败。失败会按指数退避自动重启，最多 5 次。

05运维监控

执行记录：一张表看全平台

运维监控 › 执行记录。不管是数据集成的同步、数据开发的批作业，还是工作流的某个节点，全平台所有执行都在这一张表里。这是设计如此——正因为它是一张表，"任务监控"、"告警规则"、"审计日志"才做得出跨子系统的统计。

PENDING 待下发→ DISPATCHED 已下发→ RUNNING 执行中→ SUCCEEDED 成功 /FAILED 失败 /TIMEOUT 超时 · CANCELING 取消中→ CANCELED 已取消

点取消后状态先变成取消中，不是立刻变已取消。这是诚实的：正在写库的批次要先干净地收尾。取消是真的生效——目标库会停止增长，已经写进去的行不会回滚。

任务监控

运维监控 › 任务监控提供五个口径：运行中、今日成功、今日失败、今日超时、平均耗时。都是跨子系统的——数据集成和数据开发的任务混在一起算。

告警规则

需要governance:rule:create

五种触发方式：

触发方式什么时候响
执行失败任何一次执行落到失败终态
执行超时超过任务配置的超时时间
执行耗时超过阈值没超时但比预期慢，用来提前发现劣化
执行成功但没有写入任何数据最容易被忽略的一种故障——任务绿着，数据没来
下发被拒没有可用执行器，或执行器已满
「告警频率」是抑制窗口，不是检查频率

它的意思是"同一个源头的告警，在这个窗口内只通知一次"。被抑制的那些仍然被完整记录，只是不再重复打扰你——所以在告警信息页你会看到"今日被抑制 N 条"，那个数字往往比收到的通知多得多。别把它理解成"平台漏报了"。

告警信息与审计日志

告警信息页分今日与历史两个视图，概览把"今日被抑制"单列出来。

审计日志记录谁在什么时候动了什么，失败的操作同样留痕——那往往才是要查的。审计记录只追加，不可修改也不可删除；界面上没有新建/编辑/删除按钮，接口上也没有（返回 404）。

06基础配置

这个菜单下的七项其实分属三类，放在一起只是为了操作方便。

菜单项管什么谁该管
执行器管理Flink / K8s 执行器的注册与健康状态运维
文件管理平台级 JAR、Python 包等制品，含版本数据开发
告警渠道邮件、Webhook 的收件配置运维
空间管理租户的建立、启停、成员平台管理员
角色管理角色与权限码平台管理员
用户管理账号平台管理员
凭据管理口令、密钥、令牌的托管空间管理员

凭据管理

凭据存进去就取不出来

平台用主密钥做 AES-GCM 加密存储，接口从不返回明文，也不返回密文。列表里只能看到名称、类型和引用它的对象。要换就重设一个。

对运维尤其重要的一条：主密钥（DG_SECRET_KEY）一旦用于加密过数据就不能更换，换了以后所有已存凭据都解不开。它没有内置默认值——没配置的话应用直接拒绝启动，而不是退化成一个随代码库分发的默认密钥。

告警渠道

建好渠道后点测试——注意它会真的发出去一条消息，不是检查配置格式。测邮件渠道就去收件箱看，测 Webhook 就去下游看有没有收到。

执行器与并发

平台默认与 Web 服务同进程运行，执行并发保持克制：默认同时只跑 2 个任务，队列排 64 个。这不是保守，是给 Web 请求留余量——不然界面会跟着卡。

提交了十几个任务却只看到两三个在跑，是正常的，其余在排队。真的打满了，多出来的会以下发被拒失败并给出错误码 RTM_DISPATCH_REJECTED，消息会明说"执行器已满"——这时候该做的是调大池子或加机器，不是去查平台 bug。

附录 A测试数据集

刚部署完的平台是空的，光看手册学不会。这里列的都是公开可下载、可以直接灌进测试库的数据集，按"能练到哪个功能"排。

大数据量与真实政务数据

数据集练什么怎么拿
NYC 出租车行程 千万行级。练大数据量同步的进度回报与取消——小数据量下取消一点也不像真的 NYC TLC。2022 起只发 Parquet，平台目前只读 CSV 与 JSON，需先转换
地方政务开放数据 真实的中文列名、常见 GBK 编码、不规范空值（"—"、"无"、全角空格）。这些是自己造的干净数据里永远遇不到的 盐城市数据开放平台、江苏省公共数据开放平台
实时任务没有对应的公开数据集

找不到"可以直接指过去的公开 Kafka"，这跟平台现状是吻合的——实时任务本来就需要先注册 Flink 执行器。要练的话得自己起一套 Kafka，参考 Confluent 的流水线教程。

附录 B状态机速查

三台状态机，分别管数据源、任务定义、执行。看到一个状态不认识时回来查。

数据源

状态含义能不能被任务引用
DRAFT 草稿刚建，或手工测试失败退回不能
TESTING 测试中连通性测试进行中不能
AVAILABLE 可用测通了能，只有这一个状态能
UNREACHABLE 不可达后台巡检发现连不上了不能
DISABLED 已停用人为停用不能
ARCHIVED 已归档不再使用但保留记录不能

任务定义

状态含义
DRAFT 草稿刚建或改过配置，未编译
VALIDATED 已校验编译通过，物理计划已生成
PUBLISHED 已发布可手工触发
SCHEDULING 调度中已配 Cron，会自动触发
PAUSED 已暂停不自动触发，但仍可手工触发
OFFLINE 已下线 / ARCHIVED 已归档不再执行

执行

状态含义
PENDING 待下发记录已建，还没交给执行器
DISPATCHED 已下发已交给执行器，可能在排队
RUNNING 执行中真的在跑
CANCELING 取消中收到取消，正在收尾
SUCCEEDED / FAILED / CANCELED / TIMEOUT四个终态，不再变化

附录 C出错了怎么办

先看错误码归的是哪一类

平台的错误码前缀标明了该找谁，这是排查时第一件要做的判断。

前缀归因找谁
DAT_*目标库／目标服务的问题DBA 或对端系统的负责人
MTD_*元数据问题，如读不到表结构先自查配置，再找 DBA
RTM_*运行时／执行器，多半是环境容量运维
PLT_*认证、权限、租户空间管理员
SYS_*平台自己的内部错误开发

几个常见情形

现象多半是怎么办
任务编译报"读不到源表的结构" 没有浏览过那张表，或数据源不是可用状态 去结构浏览里点开那张表；确认数据源测试通过
编译通过、执行成功，但目标表没数据 过滤条件写得太严，或字段映射一个都没配上 看执行记录里的读取行数——是 0 就是源端没取到，不是写入的问题
脱敏"配了但没生效" 配置键名拼错了 重新编译，看诊断里有没有"配置里有 N 个平台不认识的键"
提交了十几个任务，只有两三个在跑 正常，其余在排队 不用管。要提高并发找运维调 dg.runtime 的池子容量
RTM_DISPATCH_REJECTED 下发被拒 执行器已满，或该类型没有可用执行器 看消息文字区分这两种；前者调大池子，后者去注册执行器
RTM_EXECUTOR_UNAVAILABLE 实时／Python 任务需要的执行器没接入 这是环境缺口不是 bug，先接执行器
取消后状态停在取消中 正在收尾，通常几秒内落到已取消 等一下再刷新。超过一分钟不动才需要报
中文写进目标库变成乱码 文件解析任务的 charset 没配对 国内政务交换文件多为 GBK，改成 GBK 重跑
跨库迁移后查询报"列不存在" 源端是 PascalCase，目标是 PostgreSQL 迁移时打开转小写，或查询时给列名加双引号
登录后提示"登录已失效" 令牌过期，或后端重启换了签名密钥 重新登录。反复出现要请运维把 DG_JWT_SIGNING_KEY 固定下来
报障时带上 traceId

每个失败响应里都有一个 traceId。带上它，运维能在日志里一次定位到那一条请求；只说"任务跑失败了"要多花很多时间。

本手册对应平台 v0.1。文中所有状态名、错误码、参数名均取自平台实际返回；若与你手上的版本不符，以平台界面为准。

## Context

`ig_query_log` 已记录问题、状态、SQL、行数、耗时、脱敏列和错误。后端 `/api/v1/insight/queries` 只支持分页；前端还没有独立页面。

## Goals / Non-Goals

**Goals:**

- 让用户回看问数历史；
- 让管家定位失败/低质量回答；
- 重新执行经过同一 Query Gateway。

**Non-Goals:**

- 不做按用户/状态的服务端筛选（P0 客户端过滤）；
- 不做历史结果快照；
- 不做历史导出；
- 不做跨用户权限提升。

## Decisions

### 1. 只读历史，不存结果

列表只显示摘要；详情抽屉展示 SQL 和错误。重新执行调用 `/insight/ask`，不保存/复用旧结果。

### 2. 重新执行需要 `insight:ask`

`insight:read` 只允许看历史；没有 ask 权限不显示按钮，后端仍会校验。

### 3. 客户端过滤当前页

P0 用当前页数据做状态/关键词过滤，避免新增后端参数；分页仍由服务端控制。
P1 再补服务端筛选。

## Risks / Trade-offs

- [当前页过滤会漏掉其他页] → 页面提示“仅过滤当前页”，或 P1 补服务端。
- [历史 SQL 含敏感字段名] → 只展示 SQL 文本，不展示结果数据；按权限控制页面。
- [重新执行产生新审计] → 这是预期行为，审计链路保持完整。

## Migration Plan

新增路由和菜单；回滚不影响已有问数。

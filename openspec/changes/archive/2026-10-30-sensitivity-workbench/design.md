## Context

后端 `SensitivityService` 已实现规则匹配、标签 upsert、人工复核保护和扫描运行记录。前端需要把“规则 → 扫描 → 建议标签 → 人工结论”呈现为可操作工作台。

## Goals / Non-Goals

**Goals:**

- 数据管家能筛选待复核标签；
- 能查看规则与证据；
- 能确认/拒绝/调级；
- 能发起扫描并看到命中摘要。

**Non-Goals:**

- 不做规则编辑；
- 不做内容采样扫描（当前后端只有字段名/注释）；
- 不做扫描历史列表；
- 不做批量复核（P0）。

## Decisions

### 1. 单页双 Tab

规则和字段标签共享 `/metadata/sensitivity`，减少菜单层级；规则只读，标签可操作。

### 2. 复核用抽屉而不是整页跳转

复核是短动作，保留列表上下文；证据 JSON 和状态操作在一个抽屉内完成。

### 3. 扫描结果只做摘要

后端没有扫描运行列表接口，P0 扫描完成后展示 `scannedColumns/findings/duration`，然后刷新标签列表。

### 4. 数据集选择器按需搜索

1000 表环境下不一次性拉全量；复用 Catalog 数据集分页/关键词接口。

## Risks / Trade-offs

- [无法查看扫描历史] → P0 明示；P1 增加 scan run 列表 API。
- [单条复核效率低] → P0 先保证正确性；P1 批量 API。
- [标签与资产脱节] → 每行字段名链接到资产详情/字段抽屉。

## Migration Plan

新增页面和菜单；不修改现有标签/复核 API。回滚移除路由/菜单即可。
